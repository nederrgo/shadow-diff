# Monarch Status Stream — gRPC Topology Feed

Monarch serves `monarch.v1.MonarchStatusService` on **:9090**, streaming `ShadowTest` status changes to the Tusk BFF, which renders them as a live topology graph.

## The shared contract module

The wire contract belongs to neither producer nor consumer, so it is its own module: **`pipeline/pkg/monarchpb`** (`github.com/shadow-diff/monarchpb`), alongside `s3utils` / `trace` / `sample` / `replay`.

| | |
|---|---|
| proto package | `monarch.v1` |
| Go import | `github.com/shadow-diff/monarchpb` |
| generated files | `monarch.pb.go`, `monarch_grpc.pb.go` (committed; no Dockerfile runs protoc) |
| regenerate | `make monarchpb-proto` from the repo root |
| generated by | protoc-gen-go v1.36.11, protoc-gen-go-grpc v1.5.1, protoc 3.6.1 |

Monarch and Tusk each reach `monarchpb` via a `replace` directive. Tusk never imports Monarch's operator module, so it carries no controller-runtime or client-go. Ingress driver name constants live in `shadowspec` (also replaced); Tusk uses them with `components.ingress_drivers` to decide which broker-tap nodes to render.

## Value vocabulary

The message shapes are not the whole contract; the legal *values* are too. Closed sets are proto enums so a mismatch is a compile error rather than a blank node:

| Enum | Members |
|------|---------|
| `Phase` | `PROGRESSING`, `READY`, `FAILED`, `DELETING`, `DELETED` |
| `BootStep` | `VALIDATING_INPUTS`, `PROVISIONING_SINKS`, `ACTIVATING_EGRESS_TAP`, `BINDING_AMQP`, `PROVISIONING_SHADOW`, `READY`, `FAILED` |
| `CapturePhase` | `READY`, `DEGRADED`, `DISABLED` |
| `Mode` | `RECORD`, `REPLAY` |

`DELETING` is written to the CR at the start of `reconcileDelete` so a reconnect snapshot stays honest while teardown runs. `DELETED` is a **stream-only tombstone** published after finalizers are removed — the CR is gone by then, so consumers must drop their cache entry rather than treat it as a normal phase.

Every enum carries an `UNSPECIFIED = 0` member. Conversion falls back to it rather than erroring, so a CR holding a value this build does not know still streams instead of breaking the subscriber's whole feed.

Shadow role names travel as **map keys** on `ComponentStatus.shadow_roles_ready`, so they cannot be an enum. They are declared once in `monarchpb/roles.go` (`RoleControlA` / `RoleControlB` / `RoleCandidate`), and Monarch's internal role constants are defined from them.

`CapturePhase` exists because `components.kaisel_rule_active` is a bool and Monarch genuinely reports a third state: a capture rule that reconciled but is failing is `Degraded`, not merely "not ready".

`components.ingress_drivers` is a `repeated string` of resolved `spec.inputs[].driver` values (same vocabulary as `shadowspec.Driver*`). It is not a proto enum so new drivers do not require regenerating the wire enums — Tusk and Monarch share the closed set via `shadowspec`.

## Snapshot then live

`WatchShadowTestStatus` sends **one update per matching ShadowTest on connect**, then streams changes.

The snapshot is not a convenience. `patchStatusCore` skips the API write when status is semantically unchanged, so a converged ShadowTest stops producing status writes entirely — a consumer attaching afterwards would otherwise wait forever for an event that never comes.

The subscription is registered *before* the snapshot is read, so a change landing mid-snapshot is queued rather than lost. That can deliver one update twice; updates are whole-state, so applying the same one twice is a no-op.

An empty `test_name`/`namespace` in `StatusRequest` watches every ShadowTest; setting either filters.

## Publish path

| Concern | Resolution |
|---|---|
| Where updates originate | `patchStatusCore` (`internal/controller/shadowtest_resources.go`) — the single status writer, after a successful patch. Delete also calls `publishDeleted` for the stream-only `DELETED` tombstone (no CR write). |
| How the controller reaches the transport | `controller.StatusPublisher`, a one-method interface declared on the consumer side; `pkg/grpc.Hub` satisfies it. Nil disables publishing. |
| Frequency | Exactly one publish per real status transition, and none once converged. Delete emits `DELETING` once (via status patch) then `DELETED` once (after finalizers drop). |
| Slow consumers | Non-blocking send into a 16-deep per-subscriber buffer; a stream that stops draining loses frames rather than stalling `Reconcile` |
| Lifecycle | `pkg/grpc.Server` implements `manager.Runnable` and returns `false` from `NeedLeaderElection`, so every replica serves |

## Deployment

| | |
|---|---|
| flag | `--grpc-bind-address` (default `:9090`; `0` disables) |
| container port | `grpc` 9090 on `monarch-controller-manager` |
| Service | `monarch-status-grpc.monarch-system.svc.cluster.local:9090` |
| RBAC | unchanged — the controller already holds `shadowtests` get/list/watch |

Inspect it directly with:

```bash
kubectl port-forward -n monarch-system svc/monarch-status-grpc 9090:9090
grpcurl -plaintext -d '{}' localhost:9090 monarch.v1.MonarchStatusService/WatchShadowTestStatus
```
